The zero in `COMPOSITE_EXISTING_FORMAL` is intentional, not a claim that no tool composes APIs. For example, `preview_recipe_cost` uses `recipes.list` and `recipes.current_costs` but also calls unregistered BOM-draft and legacy override-preview routes. `get_recipe_detail` optionally uses current-costs but its detail GET is unregistered. `build_quotation_draft` combines registered customer/recipe lists with unregistered draft/legacy preview routes. Labeling any of these as a fully linked composite would imply more formal coverage than currently exists. Their partial registered constituents are listed in the matrix, not written into the registry.

## Direct mapping proposals

Both `compare_recipes` and `explain_cost_change` call `POST /api/cost/recipe-difference`, whose formal `cost.recipe_difference` query declares the two saved-recipe comparison and costEngine-backed output. The former adds display comparison from formal drivers; the latter exposes the formal summary. Neither computes an alternate cost. Proposed direct link: `cost.recipe_difference` for each, pending Supervisor approval.

## Proposed formal read/preview registrations

There are 20 `PROPOSED_ONLY` identifiers in the matrix, one per primary gap. They include current copper price (`market.copper_price.read`), coil cost preview (`coils.cost_preview`), coil spec options (`coils.spec_options.read`), rotor drawing history (`drawings.rotor.history.read`), workbench summary/action center, order readiness/knowledge package, quality/learning reports, recipe technical file list, and file archive targets. These are **not** registered capabilities. Several derived actions also reveal secondary unregistered routes (notably `GET /api/recipes/:id`, `POST /api/recipes/bom-draft`, `POST /api/recipes/:id/cost-preview`, quotation/order save-payload drafts, and knowledge reads). Their primary class stays derived; Phase B should decide whether to register the underlying routes independently, rather than copying a proposed ID from this report blindly.

## Cost tool boundaries and overlap

| Tool | Finding | V1 index recommendation |
| --- | --- | --- |
| `compare_recipes` / `explain_cost_change` | Direct current two-recipe difference via `cost.recipe_difference` | Expose with clear comparison vs explanation labels |

| `preview_recipe_cost` | Three paths: current-costs with no override; BOM draft with `useRecipeBaseline`; legacy saved-snapshot `cost-preview` with overrides | Defer until index can distinguish basis/branches |
| `build_recipe_bom_draft` | Official unsaved BOM/configuration and cost draft | Defer as a distinct high-level draft |
| `preview_pump_shell_cost` | Template + BOM draft, projects shell-only figure | Defer; not total recipe cost |
| `full_calculate` | `POST /api/cost/full-estimate`, free-form legacy full estimate | Defer; not saved Recipe current cost |
| `dynamic_config_cost` | `POST /api/cost/dynamic`, legacy dynamic calculator | Defer; not same-read-set scenario preview |
| `calculate_coil_cost` | Variant-safe `POST /api/coils/calculate`, with optional coil listing and other-variant notice | Expose; propose separate coil-cost preview capability |
| `get_copper_price` | `GET /api/copper-price`; only formal copper capability is *sync/write* | Expose; propose distinct read capability |

Overlap groups: (1) recipe current/override/scenario/BOM/full/dynamic cost; (2) two-recipe comparison/explanation; (3) order detail/readiness/knowledge/plan; (4) knowledge search/detail/health. Future index entries must communicate basis, read-set, saved-vs-rebuilt status, and draft-vs-execution. High-level skill-like tools worth retaining after separate review: knowledge search/detail, factory workflow plan, readiness-action plan, order detail, and quotation draft. Composite is not itself a defect; falsely claiming a one-to-one formal link is.

## Index V1 recommendation

`EXPOSE_V1`: **12**, `DEFER_V1`: **18**, `EXCLUDE_V1`: **6**. Expose core recipe/coil/order/cost/knowledge reads where the actual executor contract is mature; defer overlapping calculators, drafts and management aggregates; exclude knowledge-maintenance and factory-rule-governance telemetry from the first Owner index. Exposure remains unchanged this phase. The authoritative Phase B source should be the **actually executable Agent tool surface** (tool definitions + validated adapter + executor dispatcher + AI capability registry), enriched with verified formal links from `BUSINESS_CAPABILITY_REGISTRY`. Do not dump all 147 formal business capabilities directly into the Agent index, and do not treat proposed-only IDs as registered.
