# 私人 AI 助理：当前实现与使用

> 核对日期：2026-09-19。描述当前默认运行链；生产状态以 [发布检查清单](deployment-checklist.md) 为准。历史方案不是当前运行指令。

## 1. 用途与入口

这是工厂主人使用的私人助理。可以组合查询零件、线圈、配方、客户、订单、采购、库存和知识资料，比较正式成本。无需先把问题归入单一业务域。

Windows 本地入口为 `http://localhost:3000/ai`，登录入口为 `/login`，使用现有访问密码。普通访问认证仍保留，没有独立 owner AI 页面。默认只读助理不取得写权限；只有服务端识别出的明确业务操作命令才进入确认式写通道。明确保存个人记忆仍是独立的非业务数据命令。

## 2. 实际处理链

`聊天请求 → 服务端读写路由 → 只读 TaskEnvelope / 受保护命令计划 → 参数与标识校验 → 正式 API → EvidenceBundle / 写入确认卡 → 模型回答`

- Web 聊天与内部 `processAiChat` 统一经 `aiDispatcherV3` 进入双通道。普通对话和查询调用 `aiAssistantRuntime`；服务端仅把明确肯定式的新增、修改、删除、库存变化等操作命令交给受保护的 `aiAgentRuntimeV3`。能力询问、操作说明、否定句和不支持的模糊表达不会取得写权限。V5 Candidate 已撤除。
- `TaskEnvelope` 是内部轮次契约：固定外层记录用户目标、Capability 步骤、必答字段和展示类型，具体 `arguments` 继续使用现有 AI tool / Capability Registry schema，不维护第二套业务参数目录。每个已校验的工具调用追加为任务步骤；未调用业务工具的普通对话不会强制进入结构化展示。
- `EvidenceBundle` 只从带 `aiExecutionEvidence` 的本轮正式 Query/Preview 回执提取展示事实；模型文字、历史金额、未验证工具成功和纯语义候选不进入证据包。当前 Presenter V1 覆盖配置 BOM 成本和权威业务规则：模型回答保留必答字段时继续使用模型表达；字段遗漏、金额守卫降级为笼统文案或本地 600 字裁剪删除核心配置时，从证据包确定性生成简短底稿。底稿在裁剪之后生成，不再二次丢失必答字段。
- AI 输入框支持单轮 Provider 偏好：`默认` 继续使用系统路由，`本地模型 / DeepSeek / Kimi` 仅选择已配置项。手工选择会同时切换该模型对应的上下文和工具策略，仅影响后续发送的请求，不修改全局运行设置；手工模式不跨模型自动降级。
- 回答统计的 tok/s 不再用“completion token ÷ 整次模型请求耗时”计算，因为该耗时包含 TTFT，会严重低估短回复的 DeepSeek 生成速度。本地 llama.cpp 优先使用原生 `timings`；其他提供商仅在有足够 token、多个内容分片和可测生成区间时显示“生成速度·估算”，否则显示“暂无统计”。
- 业务查询的本轮取证要求适用于本地、DeepSeek和Kimi，与短名单开关无关。复用工具相关性描述识别查询目标，云端继续开放完整只读目录；首次尚无本轮结果时要求模型调用正式工具。模型跳过查询的正文不发送，最多要求一次补查；仍未查询则返回没有可验证结论。历史回答只能用于指代，不能复述为当前名称、库存、价格或状态。普通闲聊及只复述用户拟定价格的未执行写请求不因此强制读库。
- 模型调用统一经过 Provider Registry。`local` 模式只使用局域网 OpenAI 兼容模型，异常时直接报错，不调用云端；`local-first` 模式仍只在网络错误、超时、限流或 5xx 且 DeepSeek 已配置时降级。局域网模型无 API Key 也可运行，地址只允许 localhost 或私网 IP；Executor、正式 API、业务证据和写入边界不因模型来源改变。当前局域网服务为 `http://192.168.31.111:8080/v1` 上的 `Ornith-1.5-35B-A3B-APEX-i-compact.gguf`（纯文本模型，32K 上下文，Q4 KV，单推理槽，默认关闭 thinking，`LOCAL_AI_VISION_ENABLED=false`）；模型身份是部署事实，可在系统设置中按实际服务改写。部分局域网服务的对话模板要求 system 消息只能出现在开头（llama.cpp 的 Jinja 模板会直接报错），请求层按 Provider 能力把这些服务的中途 system 指令按原顺序并入首条 system 消息，角色交替、工具消息顺序和云端提供商行为不变。
- 完整目录由能力注册表生成。只读通道开放全部已登记 Query/Preview，并允许跨类型、跨业务组合；本地两种模式默认先依据当前问题的业务域、工具描述和输入契约生成 1–8 项短名单。命令通道先由服务端锁定 `mode=command` 和最小业务域；字段明确的单零件录入与修改会锁定正式写能力，并从当前原话确定性提取现有 tool schema 字段，不再依赖模型生成结构化计划。`将/把某零件修改成...` 属于明确命令；`刚才录入的零件` 只允许绑定同一所有者、同一持久会话最近 20 条助理消息内带正式写回执的 `create_part` 结果，找不到可信回执时不猜测型号。字段不完整或目标无可靠依据时才交给模型澄清。写工具首轮固定 `allowWrite=false`，只生成绑定登录主体、能力和规范化参数的确认卡；用户确认后才经 `/api/ai/confirm-tool` 调用正式 API。确认卡中的业务参数可人工编辑，修改后必须经 `/api/ai/confirm-tool/preview` 重新通过 tool schema 与现有写前 Preview；新卡签发后旧 token 失效，新卡仍需用户手动确认。普通闲聊不发送工具 schema，`AI_LOCAL_TOOL_SHORTLIST_ENABLED=false` 仅影响只读短名单，不扩大写权限。
- 已有在售配方作为完整配置基准，明确变更项覆盖基准，其余电缆、出水口、辅料和人工等保留。私人助理调用前省略用户没有提及的浮球、电缆、包装和可选配件覆盖，避免模型默认 false/空数组删除原配置；正式 BOM 服务选择唯一匹配基准，多候选返回供选择；包装按角色替换，不能把换箱理解成删除其他辅料。按当前价格重算，不拿历史保存总价当当前成本，结果列出配置基准。
- 经营概览使用 `get_dashboard_summary` 的正式回执生成紧凑投影，只保留订单、财务、库存和待处理摘要。缺货零件和采购大明细仍保留在原始回执中，不进入回答模型上下文。单一看板概览由领域 Presenter 确定性渲染，金额按订单总盘路径去重，并区分采购完成与已完成订单口径。
- 两个明确的 `规格-片数` 简写与成本比较意图同时出现时，默认解析为线圈对比；运行器分别调用 `calculate_coil_cost` 并由 Presenter 输出两侧成本和差额，不再把简写传给 `compare_recipes`。问题明确说“配方/成品/产品”且未说线圈时，仍按配方对比处理。
- 大型零件列表默认给模型完整总数、分类/供应商汇总和每类最多 3 个样本；用户明确要求“全部、完整、逐条、明细”时，才按分类以紧凑元组提供全部 ID、型号、当前单价、库存和供应商。客户历史查询只向模型提供客户名、报价/订单数量和按用户可见顺序排列的报价摘要，不重复发送完整 BOM、采购快照和订单明细，也不暴露内部报价 ID。页面始终持有完整原始回执，摘要不会改变正式查询范围。
- 本地模式通过 llama.cpp 的 `chat_template_kwargs.enable_thinking=false` 关闭默认隐藏思考，工具轮和最终回答分别限制在 384 和 512 tokens；项目与局域网 llama.cpp 均使用 32K 上下文，模型主机配置 8 GiB 低优先级 swap 作为 OOM 兜底，`vm.swappiness=10`，正常推理仍优先使用物理内存。提示词要求最终回答限制在 300 个中文字符或 12 个短要点以内；运行器还会删除完全重复的段落，并在用户未明确要求完整明细时以 600 字符作为异常输出兜底上限。用户明确要求完整明细时可展开到单轮上限，不改变正式查询范围。
- 请求执行期间实时显示当前阶段和已用时间。不需要业务工具的普通对话会随模型生成实时显示正文；业务查询先完成工具回执和证据校验，再显示最终结论。每条完成回答在消息底部显示实际模型、`tok/s`、总耗时、首条内容延迟、输入/输出 Token 和工具调用耗时。Token 只使用供应商 usage 尾帧；缺失时显示“暂无统计”而不估算。`tok/s` 优先使用 llama.cpp 等供应商返回的原生生成计时并标记为“生成速度”；缺少原生计时时使用输出 Token 除以模型调用耗时并标记为“有效速度”。精确速度由尾帧确定；运行统计随助理消息元数据保存，重开历史会话仍可查看。
- 订单详情给模型的视图默认仅包含订单身份、状态、产品和数量摘要；用户明确询问采购、库存、缺料或待办时才附带对应结构化摘要。原始 BOM、采购和待办 JSON 仍保留在正式回执和页面详情中，不送入回答模型占用上下文。
- 正式数据与成本由 API/service 负责。模型可以决定先查配方 A、再查 B 或调用 `compare_recipes`，成本差额也须取正式计算结果。
- 模型反问要求重复提供已有名称或确认是否继续查询时，进行至多一次完成性复核，允许用已有名称跨正式目录补齐事实。正式回执已有候选歧义时不强行继续；必要业务选择仍向用户澄清。该复核沿用同一工具/轮次预算，不额外放宽权限。完成性复核和金额纠错均不把未发送草稿当成历史回答，最终回复须独立完整，不能只写“补充上文”。
- 参数经工具唯一 schema 校验，标识须有用户输入或正式结果依据。只读工具漏传对象字段时，只允许从当前用户原话中唯一明确的型号补齐；`规格-片数` 线圈简写只从当前最新用户消息解析，覆盖模型对同一 `spec/sheets` 的错误拆分，旧消息里的其他线圈数字不能制造多候选或授权本轮参数。用户回复候选序号或唯一名称/规格片段时，只允许绑定同会话上一轮、同一工具返回且带正式执行证据的候选 ID。补齐后仍执行统一 schema、实体解析和歧义检查；无法验证的字段继续拒绝，并把具体缺失项交给模型纠错。相似名称不能自动替换目标，多候选根据用户选择继续查询；“两个都看”可分别查询。用户口语粘在名称后的语气助词和标点（`V550的`、`V550 吧`、`V550呢？`）在解析前剥离，原样名称仍优先精确匹配，正式名称本身以这些字结尾时不被误剥离；剥离后零命中就明确回答“不存在”并报出剥离后的查询，多条命中走候选澄清，两种结果不互相冒充，不把用户原话片段当成实体名回显。
- 上一轮结果与原问题绑定主体及 `conversationId`，内存会话有效期 15 分钟，最多 200 个。同会话并发请求会拒绝。Web 的 `chat-<ID>` 会话可从数据库中最近 20 条助理消息恢复带正式执行证据的候选，因此进程重启或一次失败续问后仍可处理“普通的”“第一个”等选择；恢复的候选工具即使不在当前短回复生成的本地工具短名单中，也必须加回本轮目录并执行正式重查。恢复结果仍按会话所有者隔离。实时价格、成本、库存和状态仍需本轮重查。上轮明细过大时保留已验证成功的试算对象和参数摘要，用于“其他不变”的连续变更；不携带旧金额，不从被省略的候选中自动选择。
- 保存的聊天历史与模型上下文不同：对话可持久保存，普通闲聊使用最近消息；本地业务查询只把当前用户请求、可信服务端候选和正式工具回执送入当前执行轮，不重发旧助手自然语言结论，防止上一轮错误或重复正文污染新的业务判断。只要本地短名单开放了业务工具，本轮至少要取得一次正式工具回执；模型首次跳过时重试一次，连续跳过则停止并明确没有可验证结论。对于包含明确 `规格-片数` 的线圈与配方关系查询，模型漏掉任一侧时，运行器按已解析规格确定性补发缺少的只读工具；没有明确规格时仍由模型补齐或安全停止。知识检索的模型视图省略索引拼接文本及已解析 JSON 副本；重复正文、片段、元数据只在本轮首次完整展示，后续以 documentRef 引用，内容变化重新展示，来源和匹配等级始终保留。业务规则与摘要中完全重复且已在正文出现的文字合并展示；页面及执行证据保持原始回执。列表给模型简要字段与详情入口，原始工具结果继续用于页面明细和执行证据；过大结果、轮次耗尽或接口失败必须明确未完成范围。
- 正式查询明确目标不存在时，模型视图保留目标及负结果并提示结束该目标的重复扩搜；相同已验证负查询不再重复访问 API。预算耗尽仍列出已核实的缺失目标，不把已有结论覆盖成一句通用错误；其他独立问题仍可读取。成功且完整的零结果回执会提示只在 appliedFilters 范围内没有匹配记录，避免重复扩搜；分页未结束、来源未验证或接口失败不作空结果结论。用户用型号简称（`V550`、`12-120` 这类）问成本或资料而正式配方目录里没有该成品型号时，executor 另做一次有界跨目录探测，把正式泵壳模板和零件目录里的同名候选（只带身份，不带价格与库存）附在失败回执上，`error` 仍是“未找到配方”；模型空手反问或长回答被本地裁剪时，运行器按这批正式候选确定性补一行候选清单，正文已经点到任一候选就不重复，因此不再出现“没找到，请确认你要查哪一项”而没有任何候选的空手澄清。
- 金额检查只采纳有正式执行证据的结果，包括线圈铜价基数；未验证数据、ID 和线重不能充当金额。金额检查覆盖正文及 Markdown 表格的金额列，表头统一标元不能绕过本轮证据检查。没有本轮查询依据却生成金额草稿时，纠错轮要求模型调用只读工具，而不只是口头提醒重查；仍受原轮次预算限制。金额回答无法核对时，可回显 Query/Preview 的正式金额并保留方案身份，查询档案成本明确标为档案成本；正常库存等非金额回答不触发查询金额兜底。金额守卫区分“依据”和“格式”：正文已经引用本轮正式金额、只是没写货币单位时，保留模型结论正文并把正式金额表作为附加明细追加（同一正文不会重复追加已含明细的表格）；正文没有引用任何本轮正式金额、泄漏内部指令、配置尚未完成定价，或出现正式字段之外的金额声明（含四舍五入后的整数和“金额词 + 无依据数字”）时，才整段替换为正式明细。配置试算汇总保留 currentTotalCost、正式配置名称和未完全定价提示。
- 模板查询未取得正式预览就结束时，按工具结果触发一次完成性复核，不依赖反问措辞；可选配置不自动升级为必填。模板目录向模型只展示身份、基本配置和详情入口，避免多个完整 BOM 累积挤占试算空间，页面原始明细保持完整。模板搜索支持空白分隔多个关键词全部匹配，保留所有正式候选供消歧。模板结果提供已有 build_recipe_bom_draft 试算入口，已知配置可直接调用，由服务端返回默认口径、缺项和歧义，不必先查已有配方或猜测未指定参数；同时明确区分套件成本、人工费与零件目录单价，物料单价须另查正式零件目录。最后一轮撤下工具时同步通知模型查询结束，并把历史工具协议转换为带来源的查询数据，保留全部回执内容供最终回答，防止继续模仿调用格式。
- 成本预览已有总价时，最终回答不能只提原材料单价或“见上文”；遗漏正式总价将回显正式汇总。模型正文中的 DSML/XML 工具协议不作为工具调用或用户答案，最多纠正一次，仍失败则明确停止并保留已核实事实。

源码入口：`api/routes/ai/chat.cjs`、`api/services/aiDispatcherV3.cjs`、`aiProtectedCommandRoute.cjs`、`aiAssistantRuntime.cjs`、`aiAgentRuntimeV3.cjs`。HTTP 字段、错误与回执见 [API 总表](api-reference.md)，通用约束见 [API 契约](api-contract.md)。

## 3. 长期记忆怎么用

明确指令也支持“如果没有特别提示，直接用默认的线圈，记到长期记忆里”。条件规则内容完整且保存指令肯定时才保存；否定、引用、假设保存和询问不保存。回执确认后可继续本会话未完成的模板试算，续查失败不影响已保存记忆。默认偏好只决定选择方式，方案身份仍需实时查询正式目录的唯一默认，并按 coilId 试算；无默认或多个默认必须澄清。

可以直接输入：

- `记入长期记忆：我只说规格和片数问成本时，优先查线圈。`
- `列出泵壳零件时，去零件库找泵壳分类，不是模板。这点记入长期记忆`
- 同会话：`把刚才那条改成：多个线圈方案分别列出。`
- 同会话：`删除刚才那条记忆` 或 `撤销刚才记忆修改`。

这些明确命令由服务端识别并调用个人记忆 API，拿到正式回执才显示保存成功；不依赖模型口头承诺。引用、否定、假设例句不能当作保存授权。修改使用条目 ID 和版本检查，支持幂等、软删除、修订和审计。当前加载最多 100 条有效记忆，单条 1–1500 字；记忆是偏好，不是实时价格或业务事实。

回答下方“报告问题/学习正确做法”仍走原纠错候选与审核流程，与个人记忆尚未合并。两条入口的区别及回归操作见 [纠错学习与发布回归](ai-learning-release-gate-guide.md)。自由指代“把刚才那个记住”不算当前可靠支持的保存句式。

## 4. 验证与限制

用户已于 2026-09-07 确认本地人工验收通过。V1 的真实自动化结果只记录在 [发布检查清单](deployment-checklist.md)，不在各文档复制测试数量。

可用问题包括“12-200 成本是多少”“两个都看”“对比配方 A 和配方 B 的当前成本”“这张订单缺什么料，采购和库存分别怎么样”；名称须以实际数据库对象为准。

隔离本地验收使用 `node scripts/verify-personal-assistant-local.cjs --acceptance`，创建数据库副本和临时 API，不是生产验收。不能将工具成功、流正常结束或一次回答正确等同于所有场景通过。

未完成能力及覆盖缺口统一维护在 [技术债清单](technical-debt.md#6-v1-ai-助理后续事项)。历史推演、失败与实施证据见 [档案索引](archive/README.md)，不据此恢复旧框架或改变 V1 边界。
