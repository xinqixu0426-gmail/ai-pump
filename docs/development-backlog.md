# 开发待办与版本主线

> 更新于 2026-07-29。本文用于记录已完成版本、延期事项和下一阶段建议；是否上线以生产发布记录为准。

## 1. 已完成：Knowledge V6 向量检索

### 目标

在不改变现有业务事实来源的前提下，为工厂知识增加语义检索能力。用户不必输入数据库中的精确名称，也能找到表达相近的零件、配方、线圈、规则和技术资料。

向量检索只负责“找到可能相关的知识”，不能替代：

- 零件价格、库存、铜价、报价、订单状态等实时业务 API；
- `knowledge_entries` 中可追溯的原始来源关系；
- FTS5 对型号、规格、客户名和合同号等精确词的检索；
- 写操作确认、权限、审计和业务校验。

### 已完成的准备

- 当前正式库有 126 条知识，正文约 2 万字，最大单条约 1600 字。
- Windows 开发环境已验证 `sqlite-vec v0.1.9` 可加载到现有 `better-sqlite3`，并可对普通 BLOB 向量执行余弦距离排序。
- 第一阶段不部署 Qdrant、Milvus、PostgreSQL/pgvector 等独立服务，继续保持单机 SQLite 部署。
- 第一阶段不使用 ANN 虚拟表。向量保存在普通表中并做精确扫描；当前规模足够快，也更容易备份、迁移和回退。
- 推荐嵌入模型为本地 `multilingual-e5-small`，输出 384 维向量。模型支持中文和多语言，不需要把工厂资料发送给新的外部 API。

`sqlite-vec` 当前仍是 pre-v1 组件，因此必须固定版本、保留禁用开关，并在扩展加载失败时自动回退到现有 FTS/LIKE 检索。

### V6.1 向量存储与模型适配（已完成）

- 已固定 `sqlite-vec v0.1.9` 和 `@huggingface/transformers v4.2.0`，并覆盖存在安全告警的间接依赖版本。
- 已增加 `knowledge_embeddings` 表，保存 `entryId/model/dimensions/contentHash/embedding/createdAt/updatedAt`。
- 已建立本地 `multilingual-e5-small` provider，统一使用 E5 `query:` / `passage:` 前缀、均值池化和归一化。
- 模型按需加载，默认缓存到用户目录 `.cache/pump-knowledge-models`；支持自定义缓存和离线模式，API 启动不下载模型。
- `knowledge:vector-check` 和 `knowledge:model-prepare` 分别用于无下载运行时检查及首次模型缓存。
- 扩展或模型未就绪时继续使用 FTS，不阻塞现有 API。
- `/api/knowledge/vector-health` 返回扩展版本、模型、维度、缓存目录、加载错误和待生成数量。
- Windows 已完成真实模型 embedding 和 sqlite-vec 距离检索；Mac Mini ARM64 已在临时干净目录通过依赖安装、扩展加载、余弦距离、模型运行时导入和零漏洞检查。

### V6.2 增量向量同步（已完成）

- 以 `knowledge_entries.content_hash` 判断新增、更新和跳过，后台按批次生成。
- 来源删除通过外键立即清理向量，并把级联删除数量带入下一次运行统计。
- 模型名称或维度变化时断点生成新向量，覆盖完整后才清理旧模型，检索不混用。
- 模型和批次失败不回滚业务数据、文字知识或其他成功批次，并自动重试待处理条目。
- `knowledge_vector_sync_runs` 保存新增、更新、跳过、删除、失败、待处理数量和耗时，最多保留 200 次。
- 模型首次加载和批量生成在独立后台队列执行，普通业务请求和 FTS 检索不等待。

### V6.3 混合检索（已完成）

- 已同时召回 FTS/BM25 和向量结果，向量结果不覆盖精确匹配。
- 已使用稳定的 RRF 融合排序；标题、来源标识及型号、规格、客户名、合同号等元数据的精确命中优先。
- 已返回 `matchMode/exactMatch/keywordRank/vectorDistance/finalScore`，便于诊断。
- `entryType/sourceTable` 过滤在两条检索链路中保持一致。
- 查询向量、模型或 sqlite-vec 失败时自动回退 FTS/LIKE，不伪装为语义检索成功。
- AI 继续通过 `search_factory_knowledge` 使用统一结果，没有增加第二套知识搜索工具。
- 可用 `KNOWLEDGE_HYBRID_SEARCH_ENABLED=false` 临时关闭混合检索。

### V6.4 评测与上线（本地验收已完成）

- 已建立 11 条中文型号、别名、口语、错别字和描述性问题固定评测集。
- 已覆盖泵壳型号与用途、配方详情、线圈材质与槽眼、成品电缆、完整成本、客户报价和测试报告别名。
- 已自动对比 FTS、纯向量和混合检索的 Top 1、Top 3，并阻止精确查询或整体指标退步。
- Windows 与 Mac Mini ARM64 均已在当前代码的干净环境验证双端依赖安装、全量测试、生产构建、数据库在线备份恢复、模型首次缓存、离线加载和真实混合查询；Mac 验收使用临时目录，未改动正式服务。
- 看板已展示向量覆盖率、检索模式、待生成和模型异常，不增加人工同步入口。
- `KNOWLEDGE_HYBRID_SEARCH_ENABLED=false` 可立即回退 FTS，正式环境先保留开关观察。

### 当前验收结果

- 自动化测试 `437/437`、深度 API `130/130`、Next 生产构建 17 个页面均通过。
- 固定检索评测中，FTS Top 3 为 `2/11`，向量和混合检索 Top 3 均为 `11/11`。
- 当前数据库 127 条知识和 127 条向量完整覆盖，在线备份恢复、外键和恢复库余弦查询均通过。
- 产品用途和专用配件回答已增加证据门控：纯语义候选不能单独成为事实，已有文本证据时不会交给回答模型。
- 本机完整发布命令仅因缺少生产专用 `CORS_ORIGIN`、`SIRI_API_TOKEN` 停止；正式发布必须在 Mac Mini 生产环境重新验证这两项。

### 后续扩容条件

只有当知识切片达到数万条，并且精确扫描经过基准测试确认成为瓶颈时，才评估 `vec0` ANN 索引或独立向量服务。不能仅因“向量数据库更高级”增加部署复杂度。

## 2. 下一主线建议：V7 管理事项闭环

V6 提交并部署稳定后，优先让现有“管理待办”从一次性快照升级为可追踪的管理事项：

1. V7.1 保存首次出现、持续时间、消失和再次发生的生命周期。
2. V7.2 增加负责人、截止时间、处理状态和逾期识别。
3. V7.3 从看板和业务页面进入同一处理记录，完成后由实时规则自动复核关闭。
4. V7.4 让 AI 只读汇总待办历史和处理进展；任何状态写入继续经过确认。

## 3. 延期待办

以下事项暂不进入当前开发版本：

- [ ] AI 上下文从当前最近 10 条继续扩展。
- [ ] PDF 正文与图纸结构解析。
- [ ] 图片 OCR、图纸视觉识别和多模态问答。
- [ ] 客户报价文件自动解析和结构化导入。
- [ ] Excel 通用表格理解；现有性能测试报告和基础表格提取继续保持当前边界。
- [ ] 大规模文档切片、重排模型和复杂知识关系图谱。
- [ ] 多工厂租户隔离；当前产品继续采用每家工厂独立部署。

## 4. V6 完成标准

向量检索版本只有同时满足以下条件才可上线：

1. 精确型号、价格和库存查询不能因向量结果降低正确率。
2. 口语和同义表达的 Top 3 命中率明显高于当前 FTS。
3. 每条结果仍能追溯到 `sourceTable + sourceId` 和原业务详情。
4. 扩展、模型或向量同步失败时，现有知识搜索和业务页面仍然可用。
5. 普通测试、知识回归测试、生产构建、数据库一致性和 Mac Mini 发布检查全部通过。
