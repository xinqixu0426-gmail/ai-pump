# UI/交互约束

> 更新日期：2026-07-21。本文定义当前 Next 前端的视觉、动效和交互原则。目标是简洁、克制、可操作，避免“AI 味”的装饰堆叠。

## 1. 目标风格

参考 motion-primitives 一类组件思路：状态驱动、可组合、低装饰、微动效服务交互。

- 第一屏必须是可工作的业务界面，不做营销式 hero。
- 视觉重点放在数据、动作和状态，不放在大渐变、大阴影和装饰背景。
- 页面密度偏运营工具：紧凑、清楚、可扫读。
- 文案直接说明业务动作，不写泛化价值口号。
- 颜色使用项目 token，避免重新发明一套主题。

## 2. 动效原则

动效只用于解释状态变化，不用于装饰。

| 场景 | 可以使用 | 不建议使用 |
|---|---|---|
| 弹窗/抽屉 | 轻微淡入、位移、scale | 大幅弹跳、旋转、复杂路径 |
| 表格行状态 | 背景色过渡、轻量布局过渡 | 每行连续浮动或闪烁 |
| Tabs/Segmented | 指示器平滑移动 | 整页夸张翻转 |
| Loading | 骨架屏、按钮内进度 | 大面积品牌动画 |
| 错误/成功反馈 | Toast、inline helper text | 强烈震动、遮挡式动画 |

建议默认参数：

- 常规过渡：120ms 到 220ms。
- 页面级切换：180ms 到 280ms。
- hover/focus：80ms 到 140ms。
- 所有动效必须可被业务状态触发和复现。

## 3. 页面结构

- 列表页：顶部工具栏、筛选区、表格/卡片列表、分页或虚拟滚动。
- 表单页：主表单 + 右侧或底部摘要，复杂流程再使用步骤条。
- 详情页：基础信息、业务状态、明细表、审计/历史记录分区。
- 弹窗：只承载短表单、确认操作和轻量查看；复杂编辑使用独立页面或抽屉。
- 空态：说明当前没有什么，以及下一步可以做什么；不放大段教学文案。

## 4. 组件约束

- Next 前端使用 Tailwind + 本地基础组件，不新增 MUI / Emotion 依赖。
- motion-primitives 风格组件放在 `apps/web-next/components/motion/`，以源码组件方式沉淀，不把动效逻辑散落到页面里。
- Next 前端的按钮、链接、导航项必须优先复用 `apps/web-next/components/ui/` 下的基础组件，避免每个页面手写 hover 和跳转行为。
- 图标优先用现有 icon 体系；陌生 icon-only 操作必须有 tooltip。
- 卡片只用于重复项、弹窗内容或明确的工具容器，避免整页层层套卡片。
- 表格操作要稳定：搜索、筛选、行操作、批量操作、空态、错误态、加载态必须齐全。

### 无频闪交互规则

- 未实现页面不得使用真实 `<Link>`，只能使用 disabled button 或普通文本。
- Next `<Link>` 默认设置 `prefetch={false}`，避免 hover 触发路由预取或 dev 编译。
- hover/focus 只允许改变 `background-color`、`color`、`opacity`、`box-shadow`，不得改变宽高、padding、margin、border-width、font-weight、display。
- icon、badge、suffix、tooltip 不能在 hover 时 mount/unmount；需要展示时应常驻 DOM，只改变透明度或颜色。
- 导航项、按钮、分段控件必须有固定高度和稳定布局。
- 动效组件不包裹导航链接本体；页面进入/抽屉/弹窗可以有 motion，链接和按钮本体只做轻量颜色过渡。

## 5. 表单交互

- 保存按钮只在有明确提交对象时出现。
- 保存中禁用重复提交，并保留当前输入。
- 配方等成本工作台存在会导致漏算的 warning 时，保存按钮必须禁用，提交入口也必须二次拦截；这类问题使用琥珀色提示，不使用红色错误。
- 红色错误只用于真正阻止流程且需要用户立即修正的校验/API 错误。
- 后端错误原样透传为可读提示，不吞掉具体原因。
- 数字字段必须处理空值、非数字、负数边界。
- 取消、关闭、返回前如果存在未保存草稿，应给出保护或明确丢弃路径。
- 表单草稿留在页面本地状态，不能写入全局 store。

## 6. 业务不可变边界

UI 调整不得改变这些业务事实：

- API 契约遵守 `docs/api-sop.md`；
- 业务流程遵守 `docs/business-flow.md`；
- 前端状态边界遵守 `docs/frontend-state-boundary.md`；
- 成本、库存、报价转订单、订单锁价不得在 UI 层重写口径；
- 写接口成功后必须按状态边界执行硬刷新。

## 7. 页面调整检查

调整页面时建议按风险从低到高回归：

1. 全局布局、TopBar、导航和主题 token。
2. 零件、客户等 CRUD 列表页。
3. 报价和订单列表页。
4. 配方表单、订单表单等复杂写入页。
5. 采购中心、库存入库、转子出图等高风险流程。

每完成一个页面都要跑：

- `npm test`
- `npm run build`
- 页面手动回归：加载、空态、错误、创建、编辑、删除、刷新后数据一致。
