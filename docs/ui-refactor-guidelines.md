# UI/交互约束

> 更新日期：2026-08-06。本文定义当前 Next 前端的视觉、动效和交互原则。目标是简洁、克制、可操作，避免“AI 味”的装饰堆叠。
>
> 具体组件选择与代码示例见 [`docs/ui-component-guide.md`](./ui-component-guide.md)。

## 1. 目标风格

参考 motion-primitives 一类组件思路：状态驱动、可组合、低装饰、微动效服务交互。

- 第一屏必须是可工作的业务界面，不做营销式 hero。
- 视觉重点放在数据、动作和状态，不放在大渐变、大阴影和装饰背景。
- 页面密度偏运营工具：紧凑、清楚、可扫读。
- 文案直接说明业务动作，不写泛化价值口号。
- 颜色使用项目 token，避免重新发明一套主题。

## 2. 动效原则

动效只用于解释状态变化，不用于装饰。

| 场景 | 可以使用 | 不建议使用 |
|---|---|---|
| 弹窗/抽屉 | 轻微淡入、位移、scale | 大幅弹跳、旋转、复杂路径 |
| 表格行状态 | 背景色过渡、轻量布局过渡 | 每行连续浮动或闪烁 |
| Tabs/Segmented | 指示器平滑移动 | 整页夸张翻转 |
| Loading | 骨架屏、按钮内进度 | 大面积品牌动画 |
| 错误/成功反馈 | Toast、inline helper text | 强烈震动、遮挡式动画 |

建议默认参数：

- 常规过渡：120ms 到 220ms。
- 页面级切换：180ms 到 280ms。
- hover/focus：80ms 到 140ms。
- 所有动效必须可被业务状态触发和复现。

## 3. 页面结构

- 全局工作台：左侧业务导航常驻，中间业务页面优先获得宽度，业务 AI 默认收起为右下角入口。打开后默认以覆盖层出现，宽度可在 420px 到 720px 间拖动；1600px 以上允许固定为右栏，用户也可随时全屏。系统记住 AI 的开关、固定状态和宽度，AI 会话选择在关闭、重新打开或刷新后自动恢复；独立 AI 工作台不重复挂载右栏。
- 全局导航：桌面端按业务域在左侧常驻展开，一级分组只承担信息分层，二级页面入口直接可见；窄屏使用一次打开的侧滑导航，不再使用需要逐组展开的下拉菜单。
- 响应式降级：小于常规桌面断点时，业务页面独占主区，左侧导航和右侧 AI 分别退化为按需抽屉；任何断点都不能为了固定展示 AI 而把业务区压成窄屏。
- 列表页：顶部工具栏、筛选区、表格/卡片列表、分页或虚拟滚动。
- 表单页：主表单 + 右侧或底部摘要，复杂流程再使用步骤条。
- 详情页：基础信息、业务状态、明细表、审计/历史记录分区。
- 响应式断点按侧栏占用后的有效内容宽度判断，不能只按浏览器 viewport 假设桌面表格一定放得下。
- 中窄内容区优先改为单列或卡片列表；当字段可以分主次展示时，不让主列表依赖横向滚动。
- 管理中心类长页面按任务拆分工作区；超过 30 条的重复条目必须分页或虚拟滚动，避免一次渲染整库内容。
- 页面主任务只保留一个纵向滚动容器；历史、日志等辅助内容可进入抽屉，并由抽屉独立滚动。
- 移动端首屏优先保留主操作、检索和首条业务数据；多张桌面指标卡应合并为一条紧凑摘要，避免把列表推到首屏之外。
- “全部类别”视图用于扫描，不用于完整铺开每类明细；默认展示少量代表项，并提供明确的单类别聚焦入口。
- 系统设置等低频高风险长表单按任务域拆分工作区，但共享同一份草稿和统一保存动作；切换工作区不得丢失输入。
- 设置未变化时禁用保存；存在未保存修改时必须给出可见状态，并在刷新或关闭页面前阻止静默丢弃。
- 弹窗：只承载短表单、确认操作和轻量查看；复杂编辑使用独立页面或抽屉。
- 空态：说明当前没有什么，以及下一步可以做什么；不放大段教学文案。

## 4. 组件约束

- Next 前端使用 Tailwind + 本地基础组件，不新增 MUI / Emotion 依赖。
- motion-primitives 风格组件放在 `apps/web-next/components/motion/`，以源码组件方式沉淀，不把动效逻辑散落到页面里。
- Next 前端的按钮、链接、导航项必须优先复用 `apps/web-next/components/ui/` 下的基础组件，避免每个页面手写 hover 和跳转行为。
- 弹层统一使用 `Dialog`、`ConfirmDialog`、`Drawer`；由基础组件负责 Portal、焦点陷阱、Escape、焦点恢复、滚动锁定和层级。页面不得再次手写 `fixed inset-0` 遮罩。
- 删除、覆盖、重复创建和放弃未保存修改必须使用 `ConfirmDialog`，不得调用浏览器原生 `window.confirm()`；确认文案要明确对象、后果和不可撤销性。
- 表单字段优先使用 `Field`、`Input`、`Select`、`Textarea`，统一高度、焦点、禁用和错误状态。
- 工具容器优先使用 `Panel`、`PanelHeader`、`PanelBody`；状态反馈优先使用 `InlineNotice`、`FormError`，避免复制整段边框和颜色类。
- 普通业务弹层使用基础层级；AI 助手覆盖层位于业务弹层之上，AI 内部弹层再位于助手之上。
- 图标优先用现有 icon 体系；陌生 icon-only 操作必须有 tooltip。
- 卡片只用于重复项、弹窗内容或明确的工具容器，避免整页层层套卡片。
- 表格操作要稳定：搜索、筛选、行操作、批量操作、空态、错误态、加载态必须齐全。

### 无频闪交互规则

- 未实现页面不得使用真实 `<Link>`，只能使用 disabled button 或普通文本。
- Next `<Link>` 默认设置 `prefetch={false}`，避免 hover 触发路由预取或 dev 编译。
- hover/focus 只允许改变 `background-color`、`color`、`opacity`、`box-shadow`，不得改变宽高、padding、margin、border-width、font-weight、display。
- icon、badge、suffix、tooltip 不能在 hover 时 mount/unmount；需要展示时应常驻 DOM，只改变透明度或颜色。
- 导航项、按钮、分段控件必须有固定高度和稳定布局。
- 动效组件不包裹导航链接本体；页面进入/抽屉/弹窗可以有 motion，链接和按钮本体只做轻量颜色过渡。

## 5. 表单交互

- 保存按钮只在有明确提交对象时出现。
- 保存中禁用重复提交，并保留当前输入。
- 配方等成本工作台存在会导致漏算的 warning 时，保存按钮必须禁用，提交入口也必须二次拦截；这类问题使用琥珀色提示，不使用红色错误。
- 红色错误只用于真正阻止流程且需要用户立即修正的校验/API 错误。
- 后端错误原样透传为可读提示，不吞掉具体原因。
- 数字字段必须处理空值、非数字、负数边界。
- 取消、关闭、返回前如果存在未保存草稿，应给出保护或明确丢弃路径。
- 表单草稿留在页面本地状态，不能写入全局 store。

## 6. 业务不可变边界

UI 调整不得改变这些业务事实：

- API 必须遵守 `docs/api-contract.md`，变更流程执行 `docs/api-sop.md`；
- 业务流程遵守 `docs/business-flow.md`；
- 前端状态边界遵守 `docs/frontend-state-boundary.md`；
- 成本、库存、报价转订单、订单锁价不得在 UI 层重写口径；
- 写接口成功后必须按状态边界执行硬刷新。

## 7. 页面调整检查

调整页面时建议按风险从低到高回归：

1. 全局布局、TopBar、导航和主题 token。
2. 零件、客户等 CRUD 列表页。
3. 报价和订单列表页。
4. 配方表单、订单表单等复杂写入页。
5. 采购中心、库存入库、转子出图等高风险流程。

每完成一个页面都要跑：

- `npm test`
- `npm run build`
- 页面手动回归：加载、空态、错误、创建、编辑、删除、刷新后数据一致。
