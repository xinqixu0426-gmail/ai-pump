# 近期新增代码审核记录（2026-06-14）

## 背景

本次审核范围覆盖近期新增的“型号变体 + 叶轮参数 + 配方技术档案”功能，重点检查是否存在阶段一遗留代码、重复解析、状态互斥不清、重复保存逻辑和新增字段未接入的问题。

## 已清理内容

1. 去除技术档案重复解析逻辑
   - 技术档案 JSON 解析统一使用 `StepTechnicalData.tsx` 中的 `parseTechnicalDataJson`。
   - 技术档案字段标签统一使用 `TECHNICAL_DATA_LABELS`。
   - `RecipeDetailModal` 不再维护一份重复的解析函数和标签表。

2. 规范技术档案保存格式
   - 只保存已定义字段。
   - 保存前统一转字符串并 trim。
   - 空字段不写入 JSON，避免数据库中累积无意义空值。

3. 优化型号变体与泵壳模板互斥逻辑
   - 选择普通泵壳模板时，自动清空型号变体和叶轮参数。
   - 清空型号变体时，同时清空由变体带入的模板与叶轮参数，保证页面状态符合“变体和模板只能二选一”。
   - 叶轮参数清空和应用变体参数收敛到独立 helper，避免重复 setState。

4. 增加变体级长螺丝自动匹配
   - 型号变体新增“长螺丝固定系数”。
   - 配方录入选择型号变体时，模板中的“不锈钢长螺丝”按 `机筒长度 + 固定系数` 生成型号。
   - 保留模板原型号前缀，例如 `6*160` 会保留 `6*`，只替换长度段。

5. 补齐未保存提醒覆盖范围
   - 新增型号变体、叶轮参数、不锈钢机筒长度、技术档案后，页面离开保护也会识别这些编辑内容。

## 保留的设计

1. 型号变体仍作为配方录入的上层选择
   - 变体负责带入泵壳模板、线圈规格、线圈片数、机筒长度和叶轮参数。
   - 配方最终保存快照字段，后续变体改动不反向影响历史配方。

2. 叶轮不再作为普通零件计价
   - 叶轮属于整套壳体配套参数，只记录型号、厚度、直径、叶片数。
   - 成本仍由泵壳模板承担，不额外加入零件成本。

3. 长螺丝仍保留在泵壳模板固定配件中
   - 模板用于记录这套壳体包含长螺丝这一配件。
   - 变体只负责覆盖随机筒长度变化的型号长度。
   - 成本匹配使用生成后的长螺丝型号，仍从零件库价格读取。

4. 技术档案使用配方级 JSON 字段
   - 当前阶段先支持结构化常用字段：转子尺寸、功率、电压、电流、频率、测试报告号、测试日期、测试摘要。
   - 后续如果要上传 PDF/图片测试报告，可在此基础上增加附件表，而不是把文件塞进 JSON。

## 验证建议

每次改动后至少执行：

```bash
node --check api/db.cjs api/routes/recipes.cjs api/routes/modelVariants.cjs api.cjs
npm run build
```

手工验证路径：

1. 进入 `/recipe-form`。
2. 选择一个型号变体，确认模板、线圈、机筒长度、叶轮参数自动带入。
3. 确认“不锈钢长螺丝”型号按 `机筒长度 + 固定系数` 自动变化。
4. 清空型号变体，确认模板选择也被清空。
5. 选择普通泵壳模板，确认型号变体和叶轮参数被清空。
6. 填写技术档案并保存，进入配方详情确认可正常显示。
