# 业务流程说明

> 更新于 2026-07-23。本文是当前版本的业务流程基准。后续新增功能可以调整页面结构和交互方式，但不得改变这里定义的写库点、成本快照边界和状态流转语义。

## 1. 总流程

```text
维护基础数据
  -> 建立泵壳模板
  -> 创建配方：选择泵壳、线圈和选配
  -> 保存成本快照
  -> 客户报价
  -> 报价转订单或直接创建订单
  -> 生成采购清单和生产待办
  -> 采购中心登记下单进度
  -> 订单详情登记到货和分批入库
  -> 采购完成后人工关闭订单
```

## 2. 业务对象边界

| 对象 | 职责 | 不承担的职责 |
|---|---|---|
| 零件 | 维护型号、分类、供应商、价格、库存和备注元数据 | 不保存配方选择结果 |
| 线圈 | 维护标准直径、俗称、材质、槽眼和测试/正式绕组方案；正式方案记录片数、铜重、铁芯单片价、加工费、默认线径/电容及主副绕组备忘 | 不维护材质默认单价；测试/停用方案不参与正式成本；配方保存时生成快照；绕组技术备忘不参与成本 |
| 泵壳模板 | 保存泵壳套件或自由搭配规则、人工工资、表面处理工艺和转子默认参数；套件模式引用零件库整套泵壳，自由搭配的组合名称可手输或选择泵壳型号，组件型号只能绑定零件库“泵壳搭配”分类；机筒从铝机筒、不锈钢拉伸筒、铁机筒中选择，只有不锈钢拉伸筒按长度动态计价 | 不代表最终产品 BOM；自由搭配模板名不承担库存 |
| 常用配置（历史兼容） | 保存同一模板下的高频线圈、机筒、长螺丝和叶轮组合 | 不作为新建配方的必经步骤；修改后不反写历史配方 |
| 配方 | 保存产品 BOM、动态配置、人工管理费、成本和技术参数快照 | 不随零件或模板后续改价自动变化 |
| 报价 | 基于配方做客户级价格和配置覆盖 | 不修改原配方 |
| 订单 | 保存客户、合同、订单明细、锁定成本、售价、采购清单和待办快照 | 不反向修改报价或配方 |
| 采购中心 | 按未完成订单聚合采购需求并标记采购进度 | 不增加库存 |
| 配方库存视图 | 按配方 BOM 展示配件当前库存和状态 | 不执行生产或修改库存 |

## 3. 写库与只读边界

| 流程 | 主要入口 | 是否写库 | 写入内容 |
|---|---|---:|---|
| 零件新增/修改/删除 | `/api/parts`、`/api/parts/:id` | 是 | 零件基础数据；更新和删除必须走 `safeUpdate` / `softDelete` |
| 批量库存增减 | `/api/parts/batch-stock` | 是 | 只改 `parts.stock`；入参只接受 `{ partId, delta }` |
| 线圈新增/修改/删除 | `/api/coils`、`/api/coils/:id` | 是 | 定子组合、绕组方案状态、可选绕组技术备忘和计算后的 `cost` |
| 模板新增/修改/删除 | `/api/templates`、`/api/templates/:id` | 是 | 泵壳模板、组件结构、工资默认值、转子默认参数 |
| 模板成本/默认配方预览 | `/api/templates/:id/cost`、`/api/templates/:id/default-recipe` | 否 | 只返回计算结果或草稿 |
| BOM 草稿 | `/api/recipes/bom-draft` | 否 | 只生成标准化 BOM 草稿 |
| 配方成本草稿 | `/api/recipes/cost-draft` | 否 | 只生成保存前成本快照草稿 |
| 配方保存/修改/删除 | `/api/recipes`、`/api/recipes/:id` | 是 | 配方 BOM、成本快照、技术参数；可能自动新增缺失长螺丝零件 |
| 当前配方成本参考 | `/api/recipes/:id/cost` | 否 | 只按当前基础数据重算参考价 |
| 报价覆盖试算 | `/api/recipes/:id/cost-preview` | 否 | 只按配方快照和覆盖项试算 |
| 客户新增/修改/删除 | `/api/customers`、`/api/customers/:id` | 是 | 客户档案和默认利润率 |
| 报价新增/修改/删除 | `/api/quotations`、`/api/quotations/:id` | 是 | 报价头、状态、明细 JSON、总成本和总报价 |
| 订单采购计划 | `/api/orders/purchase-plan` | 否 | 只生成采购清单和待办草稿 |
| 订单新增/修改/删除 | `/api/orders`、`/api/orders/:id` | 是 | 订单头、明细、锁定成本、售价、采购清单、待办和状态 |
| 采购中心整项下单 | `/api/orders/purchase-items/batch` | 是 | 更新活动订单采购项的下单数量；不入库 |
| 采购进度与分批入库 | `/api/orders/:id/purchase-items/progress` | 是 | 更新下单/到货/入库数量；仅入库增量在同一事务内增加库存 |
| 一次性全部入库 | `/api/orders/:id/complete-purchase` | 是 | 把剩余计划登记为下单、到货和入库，并进入采购完成 |
| 配方库存状态 | `/api/recipes/:id/inventory-status` | 否 | 普通配件读取零件库，线圈转子读取独立线圈库存；只返回当前库存和状态 |
| 转子出图 | `/api/rotor/draw`、`/api/rotor/chat` | 是 | 写入出图任务和历史记录 |
| 转子参数暂存 | `/api/rotor/save` | 是 | 保存 `status=saved` 的历史记录 |

## 4. 成本快照规则

成本分三类，业务实现和页面展示都不能混用：

| 成本类型 | 生成时机 | 允许变化 | 用途 |
|---|---|---|---|
| 当前重算参考 | 查看或手动试算时 | 会随零件、线圈、铜价、设置变化 | 风险提示、人工复核、AI 查询 |
| 配方保存快照 | 新建或修改配方保存前 | 保存后不自动变 | 配方详情、报价默认基线、订单来源 |
| 订单锁定成本 | 创建订单、报价转订单或追加订单明细时 | 保存后不自动变 | 订单利润、历史追溯、采购和生产依据 |

约束：

- 配方保存必须通过 `POST /api/recipes/cost-draft` 生成保存快照。
- 配方保存 payload 和正式写入口必须检查完整 BOM；任一项目的快照单价缺失、无效或小于等于 0 时阻止保存，并提示先补齐零件型号和单价。
- 报价覆盖必须通过 `POST /api/recipes/:id/cost-preview` 试算。
- 报价转订单必须保存展开后的 BOM 快照，不能只保存 overrides。
- 订单创建和追加明细优先使用配方 `savedTotalCost`；没有保存成本时才允许回退当前重算参考。
- 前端可以有展示级预览，但正式保存、报价和订单不得使用前端自算成本作为权威值。

## 5. 报价流程

1. 选择客户，带入客户默认利润率。
2. 选择基础配方，读取配方保存快照作为默认成本基线。
3. 客户只可覆盖是否带浮球、电缆米数、外包装（牛皮纸箱/彩印箱/木箱）、泡沫型号和是否含珍珠棉；线圈直径、材质、槽眼、片数和线径沿用配方。
4. 覆盖项通过 `POST /api/recipes/:id/cost-preview` 试算。
5. 报价保存时后端重新试算，并把完整 `bomSnapshot`、`costSnapshot`、覆盖参数、单位成本和售价写入 `quotations.itemsJson`。
6. “报价中”超过一个月会在读取列表时自动标记为“已过时”。

禁止事项：

- 报价覆盖不得修改原配方。
- 报价保存不得只保存 UI 临时状态，必须能从 `itemsJson` 复原明细。
- 报价转订单不得复用未展开的 overrides 作为订单 BOM。

## 6. 订单流程

### 6.1 直接创建订单

1. 填写客户、合同号和备注。
2. 添加一个或多个配方明细。
3. 每个明细写入配方名、规格、数量、单位成本、利润率、单位出厂价和 BOM 快照。
4. 调用 `POST /api/orders/save-payload-draft` 生成保存 payload，后端会生成采购清单和待办草稿。
5. 保存订单，初始状态为 `待确认`；人工确认后进入采购流程。

### 6.2 报价转订单

1. 从报价明细读取客户、数量、报价单价和保存时已经展开的 BOM/成本快照。
2. 调用 `POST /api/quotations/:id/order-draft` 预览订单及采购计划。
3. 确认后调用 `POST /api/quotations/:id/convert`。
4. 后端在同一事务内创建订单、保存报价与订单关联并把报价更新为 `已转订单`。
5. 同一报价重复转单返回 409；转单后不允许再修改报价明细。

### 6.3 订单状态

| 状态 | 含义 | 典型触发 |
|---|---|---|
| 待确认 | 直接创建后尚未确认核心明细 | 新建订单 |
| 待采购 | 已确认，尚未登记下单 | 确认订单 |
| 采购中 | 已有下单、到货或部分入库 | 数量进度自动推导 |
| 采购完成 | 全部计划数量已入库，但订单尚未关闭 | 数量进度自动推导 |
| 已关闭 | 业务事项已结束 | 采购完成后人工关闭 |
| 已取消 | 订单不再继续执行 | 待确认/待采购/采购中填写原因后取消 |

订单状态不能任意倒退。采购中和采购完成不能手工指定；已关闭、已取消为终态。报价转订单生成的订单已经经过客户确认，因此直接进入待采购。

## 7. 采购与库存流程

### 7.1 采购清单生成

- 输入为订单明细的 `partsJson × qty`。
- 真实零件优先按 `partId` 识别，兼容数据按“型号 + 供应商”聚合，不能只按型号合并。
- 线圈转子不进入零件库；精确匹配规格、片数、材质和槽眼的正式方案按 `coilId` 识别并以“套”为库存单位。
- 插值或外推得到但没有正式方案的线圈为非库存计算项，不伪造 `partId/coilId`。
- 全部活动订单按创建顺序共享库存，前序订单占用后，后序订单只使用剩余库存，避免同一库存重复分配。
- 采购中心汇总平衡后的 `needToBuy`。
- 参数化长螺丝可以借用基础螺丝供应商，但不能扣基础螺丝库存，也不能把基础螺丝 `partId` 写给目标长度采购项。

### 7.2 采购中心

- 采购中心只聚合未完成订单的采购需求。
- 采购中心汇总 `plannedQty/orderedQty/receivedQty/stockedQty`，可按供应商和型号执行整项下单，不增加库存。
- 部分下单、实际采购价、实际供应商、到货和入库数量在订单详情逐项登记。

### 7.3 入库

- 入库发生在订单详情确认。
- 数量必须满足 `stockedQty ≤ receivedQty ≤ orderedQty`；`orderedQty` 超过 `plannedQty` 时必须明确确认超采。
- 每次提高 `stockedQty` 都只把增量加入库存，并在同一事务内记录 `stockInHistory` 批次。
- 普通零件入库前必须存在对应 `partId`，线圈转子入库前必须存在对应 `coilId`；任一校验失败时采购进度和库存一起回滚。
- 线圈采购入库增加 `coils.stock` 并写入 `coil_stock_movements`，订单号保存在流水引用中。
- 全部计划数量入库后自动进入采购完成；订单关闭是后续独立人工动作。
- `POST /api/orders/:id/complete-purchase` 是兼容的一键动作，用于确认全部剩余物料已经到货并入库，不直接关闭订单。

### 7.4 配方库存查看

- 配方详情通过 `GET /api/recipes/:id/inventory-status` 读取配件与线圈库存；线圈转子不依赖零件库。
- 按 `model + supplier` 精确匹配，必要时回退同型号。
- 页面只展示物料、库存和状态，不提供生产数量、生产确认或自动扣库存操作。
- 缺货、零件未建档和正式线圈方案缺失必须明确标记。

## 8. 知识库与 AI 会话

- `knowledge_entries` 是由正式业务数据生成的派生索引，不是新的业务事实来源。
- 同步按 `sourceTable + sourceId` 增量更新，原始数据失效时移除对应条目，并保留未变化条目的稳定 ID。
- FTS 与知识条目在同一事务内刷新；同步失败时保留上一版完整索引。
- AI 搜索结果必须能返回原始来源类型和来源 ID，业务判断仍以原资源 API 为准。
- 配方智能检查的学习反馈绑定当时的泵壳模板和配方版本；内容修改或模板变化后，旧反馈停止影响规则并进入待重新检查队列。
- 归档带有学习反馈的配方时，同一事务会立即刷新候选规则和已批准规则知识；归档证据只保留历史追溯，不再支持当前规则。
- 学习证据健康检查覆盖尚未形成候选规则的单条反馈，只提供复核队列，不自动恢复反馈、修改配方或批准规则。
- 数据质量看板的待复核反馈可按配方逐条打开，配方页会自动执行一次智能检查；用户根据当前配置重新确认对应提醒后，该反馈才重新成为有效学习证据。
- 原提醒重新出现时，页面会精确高亮并要求按当前配置重新判断；原提醒已经消失时，可确认已解决并将旧判断恢复为中性复核状态。服务端会再次执行当前配方智能检查，防止绕过页面误清理仍存在的提醒；该动作保留原始证据，不删除历史，也不会修改配方。
- 待复核任务按配方聚合；同一配方的多条反馈一次打开后按进度逐条处理，完成当前反馈后自动定位下一条，但每条仍需独立保存人工判断。
- 每次复核保存后展示规则学习刷新结果；暂时跳过只改变当前页面的处理顺序，不改变反馈状态。整组完成后清理复核参数，返回数据质量看板时重新读取健康队列。
- AI 会话完整保存在 SQLite；发送给模型的上下文只保留最近 10 条用户或助手消息。
- 历史会话中的写操作结果只用于回看，不能再次直接确认执行。

## 9. 允许调整的内容

可以调整：

- 页面布局、弹窗、步骤条、表格和筛选交互。
- 页面状态和资源缓存组织方式。
- API client 内部封装。
- 业务 helper 的文件结构。
- UI 组件库和动效实现。

必须保持不变：

- API 标准契约和路径。
- 写库点。
- 成本快照生成时机。
- 报价转订单保存展开 BOM 快照。
- 采购中心不入库。
- 入库通过订单业务动作 API；配方库存视图保持只读，零件与线圈分别使用自己的库存调整入口。

## 10. 开发检查清单

新增或调整业务功能时必须同步遵守：

- [前端状态边界](./frontend-state-boundary.md)：约束远端数据、页面本地状态、跨资源刷新和派生数据位置。
- [UI/交互约束](./ui-refactor-guidelines.md)：约束页面结构、动效、表单、表格和组件风格。

- 新页面是否只通过标准 API 入口写库。
- 保存动作是否明确调用后端权威成本接口。
- 只读预览是否没有写库副作用。
- 写操作后是否重新拉取对应资源。
- 新增 API 是否已同步 `docs/api-reference.md` 和 `docs/api-sop.md` 约束。
- 新增业务规则是否有 helper 或服务层测试，而不是只藏在页面组件里。
