# 业务流程说明

> 更新于 2026-07-12。本文是当前版本的业务流程基准。后续新增功能可以调整页面结构和交互方式，但不得改变这里定义的写库点、成本快照边界和状态流转语义。

## 1. 总流程

```text
维护基础数据
  -> 建立泵壳模板
  -> 创建配方：选择泵壳、线圈和选配
  -> 保存成本快照
  -> 客户报价
  -> 报价转订单或直接创建订单
  -> 生成采购清单和生产待办
  -> 采购中心标记采购进度
  -> 订单详情确认入库
  -> 配方详情确认生产扣库存
  -> 订单状态流转到已完成
```

## 2. 业务对象边界

| 对象 | 职责 | 不承担的职责 |
|---|---|---|
| 零件 | 维护型号、分类、供应商、价格、库存和备注元数据 | 不保存配方选择结果 |
| 线圈 | 维护规格、材质、片数、铜重、铁芯单价、加工费和默认线径/电容 | 不直接写入配方成本，配方保存时生成快照 |
| 泵壳模板 | 引用零件库泵壳型号，保存泵壳套件/自由搭配计价、人工工资、表面处理工艺和转子默认参数 | 不新建脱离零件库的泵壳型号；不代表最终产品 BOM |
| 常用配置（历史兼容） | 保存同一模板下的高频线圈、机筒、长螺丝和叶轮组合 | 不作为新建配方的必经步骤；修改后不反写历史配方 |
| 配方 | 保存产品 BOM、动态配置、人工管理费、成本和技术参数快照 | 不随零件或模板后续改价自动变化 |
| 报价 | 基于配方做客户级价格和配置覆盖 | 不修改原配方 |
| 订单 | 保存客户、合同、订单明细、锁定成本、售价、采购清单和待办快照 | 不反向修改报价或配方 |
| 采购中心 | 按未完成订单聚合采购需求并标记采购进度 | 不增加库存 |
| 生产扣库存 | 按配方 BOM 和生产数量扣减库存 | 不改变零件价格和历史成本 |

## 3. 写库与只读边界

| 流程 | 主要入口 | 是否写库 | 写入内容 |
|---|---|---:|---|
| 零件新增/修改/删除 | `/api/parts`、`/api/parts/:id` | 是 | 零件基础数据；更新和删除必须走 `safeUpdate` / `softDelete` |
| 批量库存增减 | `/api/parts/batch-stock` | 是 | 只改 `parts.stock`；入参只接受 `{ partId, delta }` |
| 线圈新增/修改/删除 | `/api/coils`、`/api/coils/:id` | 是 | 线圈基础数据和计算后的 `cost` |
| 模板新增/修改/删除 | `/api/templates`、`/api/templates/:id` | 是 | 泵壳模板、组件结构、工资默认值、转子默认参数 |
| 模板成本/默认配方预览 | `/api/templates/:id/cost`、`/api/templates/:id/default-recipe` | 否 | 只返回计算结果或草稿 |
| BOM 草稿 | `/api/recipes/bom-draft` | 否 | 只生成标准化 BOM 草稿 |
| 配方成本草稿 | `/api/recipes/cost-draft` | 否 | 只生成保存前成本快照草稿 |
| 配方保存/修改/删除 | `/api/recipes`、`/api/recipes/:id` | 是 | 配方 BOM、成本快照、技术参数；可能自动新增缺失长螺丝零件 |
| 当前配方成本参考 | `/api/recipes/:id/cost` | 否 | 只按当前基础数据重算参考价 |
| 报价覆盖试算 | `/api/recipes/:id/cost-preview` | 否 | 只按配方快照和覆盖项试算 |
| 客户新增/修改/删除 | `/api/customers`、`/api/customers/:id` | 是 | 客户档案和默认利润率 |
| 报价新增/修改/删除 | `/api/quotations`、`/api/quotations/:id` | 是 | 报价头、状态、明细 JSON、总成本和总报价 |
| 订单采购计划 | `/api/orders/purchase-plan` | 否 | 只生成采购清单和待办草稿 |
| 订单新增/修改/删除 | `/api/orders`、`/api/orders/:id` | 是 | 订单头、明细、锁定成本、售价、采购清单、待办和状态 |
| 采购中心标记已采购 | `/api/orders/purchase-items/batch` | 是 | 只更新未完成订单的 `purchaseListJson` 采购状态；不入库 |
| 确认采购入库 | `/api/orders/:id/complete-purchase` | 是 | 同一事务内增加库存，并更新订单状态/采购快照 |
| 确认生产扣库存 | `/api/recipes/:id/produce` | 是 | 重新预检后在同一事务内扣减库存 |
| 转子出图 | `/api/rotor/draw`、`/api/rotor/chat` | 是 | 写入出图任务和历史记录 |
| 转子参数暂存 | `/api/rotor/save` | 是 | 保存 `status=saved` 的历史记录 |

## 4. 成本快照规则

成本分三类，业务实现和页面展示都不能混用：

| 成本类型 | 生成时机 | 允许变化 | 用途 |
|---|---|---|---|
| 当前重算参考 | 查看或手动试算时 | 会随零件、线圈、铜价、设置变化 | 风险提示、人工复核、AI 查询 |
| 配方保存快照 | 新建或修改配方保存前 | 保存后不自动变 | 配方详情、报价默认基线、订单来源 |
| 订单锁定成本 | 创建订单、报价转订单或追加订单明细时 | 保存后不自动变 | 订单利润、历史追溯、采购和生产依据 |

约束：

- 配方保存必须通过 `POST /api/recipes/cost-draft` 生成保存快照。
- 报价覆盖必须通过 `POST /api/recipes/:id/cost-preview` 试算。
- 报价转订单必须保存展开后的 BOM 快照，不能只保存 overrides。
- 订单创建和追加明细优先使用配方 `savedTotalCost`；没有保存成本时才允许回退当前重算参考。
- 前端可以有展示级预览，但正式保存、报价和订单不得使用前端自算成本作为权威值。

## 5. 报价流程

1. 选择客户，带入客户默认利润率。
2. 选择基础配方，读取配方保存快照作为默认成本基线。
3. 可覆盖浮球、电缆、包装、线圈材质/片数和定制机筒等配置。
4. 覆盖项通过 `POST /api/recipes/:id/cost-preview` 试算。
5. 报价保存写入 `quotations.itemsJson`、`totalCost`、`totalPrice`、`status` 和备注。
6. “报价中”超过一个月会在读取列表时自动标记为“已过时”。

禁止事项：

- 报价覆盖不得修改原配方。
- 报价保存不得只保存 UI 临时状态，必须能从 `itemsJson` 复原明细。
- 报价转订单不得复用未展开的 overrides 作为订单 BOM。

## 6. 订单流程

### 6.1 直接创建订单

1. 填写客户、合同号和备注。
2. 添加一个或多个配方明细。
3. 每个明细写入配方名、规格、数量、单位成本、利润率、单位出厂价和 BOM 快照。
4. 调用 `POST /api/orders/save-payload-draft` 生成保存 payload，后端会生成采购清单和待办草稿。
5. 保存订单，初始状态默认 `待采购`。

### 6.2 报价转订单

1. 从报价明细读取客户、数量、报价单价和覆盖项。
2. 对基础配方应用覆盖项，重新展开浮球、电缆、包装、定制机筒和长螺丝。
3. 调用 `POST /api/recipes/cost-draft` 生成订单使用的 BOM 与成本快照。
4. 保存订单。
5. 将报价状态更新为 `已转订单`。

### 6.3 订单状态

| 状态 | 含义 | 典型触发 |
|---|---|---|
| 待采购 | 订单已创建，仍有采购项未处理 | 新建订单、取消采购标记 |
| 采购中 | 已开始处理采购项 | 采购中心标记部分或全部采购项 |
| 已完成 | 采购入库和生产交付完成 | 订单详情确认完成 |

状态可以人工调整，但不能绕过库存入库和生产扣库存的业务检查。

## 7. 采购与库存流程

### 7.1 采购清单生成

- 输入为订单明细的 `partsJson × qty`。
- 输出按型号和供应商聚合。
- 先扣除当前库存，再计算 `needToBuy`。
- 参数化长螺丝可以借用基础螺丝供应商，但不能扣基础螺丝库存，也不能把基础螺丝 `partId` 写给目标长度采购项。

### 7.2 采购中心

- 采购中心只聚合未完成订单的采购需求。
- 标记“已采购”调用 `POST /api/orders/purchase-items/batch`，只更新订单采购项状态，不增加库存。
- 供应商分组、采购进度和统计都是订单快照的视图。

### 7.3 入库

- 入库发生在订单详情确认。
- 入库调用 `POST /api/orders/:id/complete-purchase`。
- 后端在同一事务内增加库存，并同步更新订单采购清单和状态。

### 7.4 生产扣库存

- 生产扣库存发生在配方详情确认生产。
- 扣库存前必须按 `model + supplier` 精确匹配，必要时回退同型号。
- 库存不足或零件缺失必须明确提示。
- 生产预检可调用 `POST /api/recipes/:id/production-check`。
- 确认扣库存必须调用 `POST /api/recipes/:id/produce`，后端重新预检并在同一事务内扣减库存。

## 8. 允许调整的内容

可以调整：

- 页面布局、弹窗、步骤条、表格和筛选交互。
- 页面状态和资源缓存组织方式。
- API client 内部封装。
- 业务 helper 的文件结构。
- UI 组件库和动效实现。

必须保持不变：

- API 标准契约和路径。
- 写库点。
- 成本快照生成时机。
- 报价转订单保存展开 BOM 快照。
- 采购中心不入库。
- 入库和生产扣库存都通过各自业务动作 API；通用批量库存接口只作为底层库存增减入口。

## 9. 开发检查清单

新增或调整业务功能时必须同步遵守：

- [前端状态边界](./frontend-state-boundary.md)：约束远端数据、页面本地状态、跨资源刷新和派生数据位置。
- [UI/交互约束](./ui-refactor-guidelines.md)：约束页面结构、动效、表单、表格和组件风格。

- 新页面是否只通过标准 API 入口写库。
- 保存动作是否明确调用后端权威成本接口。
- 只读预览是否没有写库副作用。
- 写操作后是否重新拉取对应资源。
- 新增 API 是否已同步 `docs/api-reference.md` 和 `docs/api-sop.md` 约束。
- 新增业务规则是否有 helper 或服务层测试，而不是只藏在页面组件里。
