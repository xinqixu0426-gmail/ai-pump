## 本批实际改动

- 聊天与 `processAiChat` 默认进入 `aiAssistantRuntime`。不再调用两个前置规划阶段，也不按当前计划逐项限制工具；48 个已登记 Query/Preview 工具每轮可跨类型、跨业务组合。原 77 个工具的注册与业务实现保留，普通循环不开放其中的业务写工具。
- 复用 provider、SSE、取消、正式 executor、schema、API 执行证据和成本服务。保留 7 次模型轮次、10 次工具提议、上下文预算；重复成功调用复用结果，失败不删除已取得的独立事实。
- 服务端引用绑定现有主体与 conversationId，15 分钟过期，最多 200 个会话。同会话并发不能覆盖状态；不接受客户端 turnState 作为事实或写授权。
- 新增个人记忆服务和正式 GET/POST API，迁移 80 创建记忆及修订表。支持明确快捷指令保存、修改、删除、撤销，包含版本冲突、幂等、原子审计回执；首次模型选择前加载记忆。记忆写入测试使用临时库；本地服务启动前已备份本地库，启动后应用迁移供人工验收。
- 修复线圈成本工具漏掉同材质/槽眼的多套电气方案，以及默认排除测试方案的情况；只读试算接通正式 API 已有的 `includeTesting` 能力，不修改方案状态或生产绑定。
- 对模型把内部编号写成金额、遗漏已经查到的金额、复述历史金额的情况增加共用检查。金额字段支持正式数字及十进制字符串；最多一次依据修正提示，保留只读工具补齐数据，必要时直接展示正式成本预览摘要。候选目录不作为完成试算的摘要，复述用户拟定价格不强迫业务查询。它不进行成本计算，也不是全部自然语言事实的完整证明器。

### 人工验收暴露的上下文缺陷修复

本地会话 39 的“查一下最近 5 个订单”仅返回一个订单，完整嵌套快照约 30KB，仍与工具目录共同触发 token 预算；旧会话 37 随后查询成本也被上一轮大结果阻断。实际入口是新版运行器，不是旧服务。

- 新增独立模型视图：订单、报价、配方列表保留基本信息、身份及查询回执，显式标注嵌套省略字段和既有详情工具。正式 executor/HTTP 返回、SSE 明细和身份校验依据保持完整。
- 详情 JSON 无损解码；预算使用消息内容估算，避免二次序列化转义膨胀。上轮引用最多 4096 估算 token，超过时要求重查，避免旧大结果阻断下一轮。
- 预算紧张时先压缩工具说明，保留全目录与校验结构；大明细已取得时可结束工具循环并根据完整证据回答已核实部分，而非丢弃整轮答案。
- 修复正式订单列表 ID 未被旧编号校验认可的遗漏；同主体、同会话列表支持详情追问，无执行证据及跨会话候选仍拒绝。

扩展真实模型容量回归最终 5/5：订单列表→订单配置/采购详情→线圈成本，以及报价、配方列表。原始过程结果保留在 `output/assistant-acceptance/2026-09-07T07-34-44-270Z`、`2026-09-07T07-36-24-915Z`、`2026-09-07T07-38-15-635Z`；最终为 `2026-09-07T07-39-32-739Z/context-acceptance.json`。首轮脚本将“未达到数量上限”误判容量失败，后续已纠正，原记录未改写。5/5 指容量与查询链检查，并非全部回答事实无误：订单长答案仍存在把单位成本称为单价、额外延伸未请求金额等表达问题，留待整体回答质量验收，不能把容量修复等同于全部业务验收。
